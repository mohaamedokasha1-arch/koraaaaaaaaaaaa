# مركز البث الرسمي — التشغيل والنشر

ميزة مستقلة في `src/features/live`؛ لا تغيّر طبقة النتائج أو مقدّمي بياناتها. الكتالوج، قائمة القنوات، والاكتشافات الإنتاجية **فارغة عمدًا**. لا تُعرض مباراة أو إتاحة مشاهدة مفترضة، ولا توجد روابط بث تجريبية منشورة.

نتائج المراجعة التكميلية، الملفات المتغيرة، وفحوص الإيقاف/الأداء الحالية: [FOLLOW-UP.md](./FOLLOW-UP.md). سجلا CHANGES وQA يؤرشفان التنفيذ الأساسي.

## المسارات والعلم

- `/live` و`/live/<matchId>`: مدخلان نظيفان، يحوّلهما الـproxy إلى `/{locale}/watch[/<matchId>]` حسب اللغة.
- `/ar/watch`، `/en/watch`: مركز البث، أقسام مباشر/قادم/منتهٍ ومرشحات البطولة والفريق.
- `/{locale}/watch/<matchId>`: المشغّل، المصادر، توقيت المباراة، النتيجة/الدقيقة والأحداث من `/api/matches/live` **قراءة فقط**، وروابط صفحة التفاصيل والترتيب الحالية. لا تُختلق تشكيلات غير متاحة؛ يُعرض رابط البيانات الموجودة.
- `/{locale}/watch/copyright` و`disclaimer`: حقوق النشر، نموذج التواصل مع صاحب الحقوق، وإخلاء المسؤولية.
- `/{locale}/watch/admin`: إدارة JSON محمية، مخفية بـ404 إن لم تُهيّأ الأسرار والتخزين الدائم.
- `POST /api/live/report`: **Route Handler الجديد الوحيد**؛ Edge، لا يمرّر فيديو.
- صفحات البث العامة `revalidate=60`، ومعرفات ±7 أيام (حتى 100) تُولّد مسبقًا، والبقية ISR عند الطلب. الإدارة ليست ISR ولا تدخل الكاش.
- `/ar/live` و`/en/live` يظلان صفحات النتائج المباشرة الأصلية، لتجنب تغيير مسارات النتائج القائمة.

`NEXT_PUBLIC_LIVE_ENABLED` لا يعمل إلا بالقيمة `true`؛ الافتراضي `false`. هو علم **وقت البناء**: غيّره وأعد البناء/النشر، لا تتوقع تغيير حزم JavaScript المفتوحة بمجرد تغيير متغير على الخادم.

## 1. تشغيل JSON بلا Supabase

```bash
npm ci
cp .env.example .env.local
# اضبط NEXT_PUBLIC_LIVE_ENABLED=true محليًا أو في إعدادات النشر
npm run live:validate
npm run typecheck
npm run lint
npm test
npm run build
npm run start
```

- `public/live/catalog.json`: بيانات المباريات، مصادرها المرخصة، وروابط الناقلين.
- `src/features/live/data/channels.json`: قائمة YouTube المراجَعة؛ فارغة افتراضيًا.
- `public/live/discoveries.json`: مرشحون للمراجعة فقط، وليسوا جدول بث منشورًا.
- JSON في المستودع/CDN، وليس نظام ملفات Vercel وقت التشغيل. أي نشر أو تعديل في هذا الوضع يحتاج مراجعة وتغييرًا بالمستودع وإعادة نشر.
- التقارير والإدارة يحتاجان Supabase الدائم. في JSON-only البلاغ يرجع `503` والإدارة `404`؛ لا يوجد بديل وهمي في ذاكرة serverless.
- تحقق بدون شبكات أو كتابة: `npm run live:sync -- --dry-run`. حتى إن كانت مفاتيحك مهيأة، هذا الوضع لا يستدعي APIs ولا يستهلك ميزانية الاكتشاف.

## 2. تجهيز مصدر مشروع

راجع التعريفات الفعلية في `types/index.ts`؛ جميع البيانات الخارجية تُتحقق بـZod. قبل النشر:

1. خذ **معرف المباراة الموجود فعلًا** من مصدر النتائج الحالي. لا تغيّر معرفات النتائج ولا تنشئ مباراة لمجرد تشابه عنوان فيديو. يرفض مخطط المباراة مقاطع `.` و`..` والأسماء المحجوزة `admin/copyright/disclaimer`، حتى لا يفتح الرابط صفحة أخرى.
2. سجّل الفرق والشعارات والبطولة و`startsAt` بصيغة ISO UTC، و`status` المراجع (`scheduled/live/ended`). هذه بيانات ربط تنظيمية؛ حالة المباراة/القائمة لا تُستنتج من عنوان فيديو أو انتهاء العدّ التنازلي. أبقِ هذه البيانات محدثة بصفتك المشغّل.
3. كل مصدر يحتاج `id` فريدًا، `matchId` موجودًا في الكتالوج، `provider`، `sourceRef`، `priority`، اللغة/الجودة/المنطقة، وحالة الإتاحة.
4. أرفق `rights`: الأساس `official` أو `licensed`، رابط الإثبات، وقت المراجعة، ومَن راجعها. علامة «رسمي» هي مراجعة الناشر وليست شهادة قانونية آلية.
5. لـYouTube: ضع Channel ID الحقيقي في whitelist مع `enabled=true` وحقوق مراجعة، وتأكد يدويًا أن Video ID **يتبع هذه القناة** وأن التضمين والحقوق والمنطقة مناسبة. أداة النشر تمنع القنوات غير المراجعة؛ الاكتشاف الرسمي يتحقق أيضًا من بيانات الفيديو/قناته. أدوات التحقق المحلية لا تتصل بـYouTube لإثبات الملكية.
6. Twitch يحتاج قناة رسمية مراجعة. روابطه تتضمن `parent` من hostname المتصفح الحقيقي، لا `localhost` ثابتًا.
7. HLS: لا توجد استضافة إعلامية مسموحة افتراضيًا. بعد الحصول على ترخيص صريح، أضف فقط نطاق المانيفست إلى `hlsHosts`، ونطاقات المقاطع/المفاتيح اللازمة إلى `mediaHosts` في `lib/policy.mjs`، ثم أعد البناء لتحديث التحقق وCSP. عيّن نافذة زمنية ملائمة للحقوق. اختبر CORS من النطاق الحقيقي؛ **لا تضف proxy أو تجاوزًا لـCORS** إذا منع الناقل ذلك.
8. iframe رسمي/Scorebat: أدخل URL تضمين مقبولًا في السياسة، لا HTML. Scorebat discovery يحتفظ برابط تضمين مقبول فقط ويزيل query/hash؛ لا ينشر توكن API أو HTML من الـfeed. راجع شروط الخدمة والترخيص قبل الربط اليدوي.
9. أضف ناقلًا في `broadcasters` وربطه بمعرف/كود البطولة مع المنطقة وملاحظة الاشتراك. يمكن أيضًا إضافة مصدر `external` لمنصة معتمدة. رابط YouTube/Twitch/iframe المراجع يُعرض خارج المشغّل أيضًا عند فشل التضمين؛ لا يتحول رابط HLS الخام إلى «ناقل رسمي».
10. شغّل `npm run live:validate` والبناء قبل النشر. لا تملأ `reportCount` أو مؤشرات الجودة بأرقام تجريبية.

الكتالوج علني: لا تخزّن فيه service role، API keys، كلمات مرور، إثباتات خاصة، أو توكنات ليست مقصودة للمشاركة مع المشاهد. السماح بنطاق لا يمنح ترخيصًا لكل محتواه. قيود البلد/التضمين/الاشتراك تُحترم؛ لا نقدم تجاوزًا أو ضمانًا بإتاحة مجانية لكل مباراة.

## 3. Supabase الاختياري

1. أنشئ مشروعًا، ونفّذ `docs/live/supabase.sql` من SQL Editor. الهجرة قابلة لإعادة التنفيذ.
2. ابدأ بالسجل `primary` الفارغ الذي تنشئه الهجرة. أدخل المصادر عبر لوحة الإدارة بعد إعداد whitelist/حقوقها؛ لا تُطلِق إدخالًا مباشرًا من متصفح بالدور العام.
3. اضبط في النشر:

| المتغير | الاستعمال |
| --- | --- |
| `NEXT_PUBLIC_LIVE_SUPABASE_URL` | أصل HTTPS للمشروع فقط، بلا path/query/hash أو بيانات دخول |
| `NEXT_PUBLIC_LIVE_SUPABASE_ANON_KEY` | مفتاح القراءة العام؛ RLS يحمي الكتابة |
| `LIVE_SUPABASE_SERVICE_ROLE_KEY` | خادم فقط؛ RPC التقارير والإدارة والأتمتة |
| `LIVE_REPORT_SALT` | سر عشوائي ≥32 حرفًا لهوية البلاغات المموّهة |
| `LIVE_ADMIN_PASSWORD` | كلمة عشوائية ≥24 حرفًا؛ ليست للمتصفح |
| `LIVE_RIGHTS_EMAIL` | بريد حقيقي مراقَب لطلبات الحقوق، وليس سرًا |

يمكن توليد أسرار عشوائية بـ`openssl rand -hex 32` وإدخالها في إعدادات النشر؛ لا تشاركها في Git أو المحادثة.

### الأمان، البلاغات والتزامن

- `anon/authenticated`: SELECT للسجل العام `live_catalog` فقط؛ لا كتابة ولا قراءة لهويات البلاغات أو حدود الاستخدام أو الاكتشافات.
- RPC الكتابة مُتاح فقط لـ`service_role`. أوقات/عدادات التقارير تُكتب في PostgreSQL، لا في ذاكرة Function.
- الحد: 5 محاولات تقرير/10 دقائق لكل هوية؛ تكرار الهوية للمصدر خلال 15 دقيقة لا يزيد عداد البلاغات.
- 5 هويات مختلفة/30 دقيقة قد تُخفي المصدر 15 دقيقة. الهوية مشتقة من عنوان موثوق بـHMAC، وليست «5 أشخاص» مثبتين؛ NAT/VPN يؤثران في ذلك.
- Vercel يُستخدم تلقائيًا كبيئة proxy موثوقة. في استضافة أخرى **اترك** `LIVE_TRUST_PROXY_HEADERS=false` حتى يَكتب الـproxy `x-real-ip` ويزيل/يستبدل `x-forwarded-for` القادم من العميل. عند تفعيله يُتجاهل `x-vercel-forwarded-for` المزيف خارج Vercel. دون ذلك كل الزوار يشتركون في bucket محافظ، بدل السماح بإنشاء بلاغات وهمية عبر headers.
- لا يخزن التطبيق IP خامًا؛ hashes تبقى بيانات مموّهة وليست وعدًا قانونيًا بأنها مجهولة بالكامل. الوثّق سياسة الخصوصية الملائمة لبلدك.
- تنظيف السجلات الأقدم من يوم **best effort عند بلاغ مقبول جديد**؛ ليس cron حذف مستقلًا. إن كنت تحتاج احتفاظًا صارمًا، جدول تنظيف PostgreSQL مصادقًا. حذف/استبدال مصدر يمسح بلاغاته المرتبطة القديمة.
- `save_live_catalog` يقفل الصف ويتحقق من `revision`؛ الحفظ المتزامن القديم يُرفض بدل سحق تعديل أحدث. التقارير لا ترفع revision التنظيمية. عدادات المصدر نفسه تُحفظ حتى إن كان المحرر قديمًا؛ تغيير الفيديو/provider/المباراة يصفرها ويمسح تاريخ التقرير للمصدر القديم.
- لوحة الإدارة: cookie `HttpOnly/SameSite=Strict/Secure` في الإنتاج، جلسة موقعة 8 ساعات؛ دخول 5/15 دقيقة وحفظ 10/دقيقة. النشر يعيد التحقق ويُبطل ISR. يُمنع المحرر عند فشل قراءة التخزين، فلا تُنشر نسخة fallback فارغة عرضًا.
- نقطة التقارير: origin مطابق، JSON ≤1024 بايت حتى للأجسام chunked، ووقت RPC محدود. الردود: `400/413/415` إدخال، `403` origin، `404` معطل/مصدر غير موجود، `429` حد الاستخدام، `503` تخزين غير مهيأ/متعطل. لا تدّعي الواجهة تسليم بلاغ فشل.

## 4. الاكتشاف الاختياري

Workflow: `.github/workflows/live-discovery.yml`. موقوف افتراضيًا؛ اضبط Repository Variable `LIVE_DISCOVERY_ENABLED=true` **بعد** مراجعة الترخيص والميزانية.

- راقب أيضًا حصص/دقائق GitHub Actions وحجم نقل بيانات Supabase/Vercel؛ هذه الهندسة لا تضمن كلفة صفرية عند أي عدد زوار أو نوع مستودع.
- الجدولة `*/15 * * * *`، مع تشغيل يدوي. GitHub قد يؤخر الجدول؛ هذا ليس ضمان مراقبة كل دقيقة.
- Secrets: `YOUTUBE_API_KEY`، `SCOREBAT_API_TOKEN` اختياريًا؛ وللنشر الدائم `LIVE_SUPABASE_SERVICE_ROLE_KEY`.
- Repository Variable للتخزين: `NEXT_PUBLIC_LIVE_SUPABASE_URL`.
- تُدوّر القنوات: **قناة واحدة لكل slot**، وليس كل القنوات كل 15 دقيقة. بحث YouTube Live واحد (100 وحدة)، ثم metadata واحدة بحد ≤50 IDs (وحدة واحدة). تُحجز أماكن للاكتشافات الحية الجديدة وتُدوّر بقية المعرفات المرتبطة بين زيارات القناة؛ لا تُهمل المصادر بعد أول 50 معرّفًا. 96 تشغيلًا ×101 =9696 وحدة/يوم إذا احتسبنا هذه المهمة وحدها؛ الاستخدام الآخر لنفس المشروع قد يتجاوز الحصة.
- Supabase يقيد إجمالي محاولات المهمة، بما فيها التشغيل اليدوي، إلى 96 بحسب يوم Pacific. JSON وحده لا يعطي قفل ميزانية يومية موزعًا؛ راقب التشغيل اليدوي/الحصة في Google Console.
- يُحدَّث فقط YouTube ID **المربوط يدويًا مسبقًا**. لا تخمين أسماء الفرق، ولا نشر مرشح أو تغيير نتيجة مباراة تلقائيًا.
- المرشحون يُنقحون/يُدمجون، حتى 300، لمدة 7 أيام. Scorebat يأتي من API الرسمي فقط مع مراجعة الترخيص؛ لا scraping لصفحات البث.
- JSON-only: ملفات artifact، تراجعها وتضم التغييرات وتعيد النشر. الصلاحيات `contents: read`؛ المهمة لا تعمل auto-push ولا تعدّل فرعًا.
- Supabase: الحفظ عبر RPC مع revision، مع artifact للنسخة المحفوظة. كتابة الكتالوج والاكتشافات ليست transaction مشتركة؛ فشل لاحق قد يترك كتالوجًا صحيحًا مُحدّثًا، لذلك افحص حالة المهمة، لا تعتبر الخطأ rollback تلقائيًا.
- تشغيل `npm run live:sync` العادي قد يستهلك API quota ويكتب الملفات/التخزين المهيأ؛ `--dry-run` للتحقق المحلي الخالي من الشبكات/الكتابة.

## 5. المشغّل والصدق في الإتاحة

- Client-only عبر `next/dynamic` و`ssr:false`، 16:9، skeleton، fullscreen، وError Boundary محلي. **لا iframe/API مقدم أو video قبل اختيار المشاهدة**. `hls.js` لا يُحمّل إلا عند مصدر HLS بلا دعم native.
- فيديو HLS/iframe/YouTube يصل من الناقل إلى المتصفح مباشرة. لا `/api/video`، لا m3u8 proxy، لا CORS bypass ولا إعادة استضافة.
- الأولوية أولًا، والنجاح السابق المخزن محليًا يكسر تعادل الأولوية. لا نعامل load event كتأكيد تشغيل.
- محاولتان للمصدر في الجولة، tokens تمنع callbacks القديمة، تبديل معلن، ونهاية واضحة مع إعادة محاولة وروابط المنصات الرسمية.
- YouTube: API الأخطاء/حالة التشغيل؛ انتهاء live ينتقل لبديل، انتهاء highlights لا يعد خطأ.
- HLS: fatal error؛ محاولة media recovery واحدة لكل تنشيط قبل الانتقال. `playing/waiting/fragment` أحداث حقيقية، لا «سرعة سيرفر» مخترعة.
- iframe عام وTwitch: مهلة load قدرها 12 ثانية، تحكم يدوي وإقرار المستخدم بالتشغيل. قيود same-origin تمنع ضمان معرفة فشل داخلي، وقد يرفض الناقل التضمين/parent في iframe معاينة متداخل؛ الرابط الرسمي يظل المسار الصحيح.
- البلاغات مؤشرات لا إثبات سرعة أو جودة للناقل. يظهر التقطّع/عدم الإتاحة/عدم وجود قياس دون أرقام latency مصطنعة.
- الكتالوج والنتائج polling كل 45 ثانية، مخفي/offline متوقف، وإعادة قراءة عند ظهور التبويب وعودة الاتصال. ينطبق التوقف كذلك على إعادة الجلب عند الخطأ، لا مؤقت polling وحده. إذا خرجت مباراة من feed المباشر لا نخترع نتيجة نهائية: تُحفظ آخر قراءة وتُعلّم قديمة.
- ساعة الإتاحة مشتركة كل 30 ثانية والعد التنازلي كل ثانية؛ لا مؤقت مستقل لكل بطاقة. تتوقف الساعة عند إخفاء التبويب، وتُعيد احتساب انتهاء الإخفاء/إتاحة المصدر حتى إذا لم يتغير JSON. إقرار HTTP 200 للبلاغ لا يكفي دون استجابة `accepted=true` صالحة.
- المواعيد UTC، العرض يحترم cookie المنطقة الزمنية الموجودة دون جعل ISR يعتمد على cookies. ICS يظل UTC ويدعم fold أسطر UTF-8؛ العد التنازلي يتوقف عند إخفاء التبويب. انتهاء الوقت وحده لا يُعلن البث.
- CSP `frame-src` من allowlist، sandbox محدود، referrer policy، وعدم تسريب أسرار للمتصفح. حماية framing في Vercel production؛ المعاينات قابلة للعرض. للاستضافة خارج Vercel اضبط profile الإنتاج/headers المناسبة ولا تتعامل مع إعداد المعاينة كتهيئة إنتاج آمنة تلقائيًا.

## 6. الاختبارات

```bash
npm run live:validate
npm run typecheck
npm run lint
npm test
NEXT_PUBLIC_LIVE_ENABLED=true npm run build
npx playwright install --with-deps chromium
npm run test:e2e
```

`.github/workflows/live-quality.yml` يشغل هذه البوابات على PR/يدويًا ويحتفظ بأثر فشل المتصفح. بيانات Playwright/YouTube/HLS doubles في `tests/e2e/fixture-app` فقط؛ لا يضاف Route Handler تجريبي للإنتاج ولا تُنسخ هذه البيانات إلى `public/live`.

إن كان تنزيل Chromium محجوبًا، يمكن الإشارة إلى نسخة Chromium موجودة بـ`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. لا تعطّل أمان المتصفح أو CORS. ابدأ الاختبار بعد بناء **مفعّل**؛ `NEXT_PUBLIC_*` لا يتغير بحزمة بنيت والعلم مغلق.

### PostgreSQL محلي اختياري دون dependency للتطبيق

```bash
npm install --prefix /tmp/live-sql-tooling --no-save @electric-sql/pglite
LIVE_PGLITE_MODULE=file:///tmp/live-sql-tooling/node_modules/@electric-sql/pglite/dist/index.js \
  node scripts/live/check-sql.mjs
```

24 تحققًا حاليًا: migration قابلة لإعادة التنفيذ، RLS/RPC، dedup/rate/quota، الإخفاء، الحفاظ على العدادات، حذف تاريخ المصدر المتغير، تعارض revisions والتنظيف. قاعدة **ذاكرة محلية فقط**، لا اتصال بـSupabase الحقيقي. PGlite يستخدم اتصالًا داخليًا واحدًا؛ فحص طلبَي حفظ متنافسين يتحقق من conflict semantics، وليس اختبار حمل متعدد الاتصالات على Supabase.

التبعيات المضافة ومبرراتها: `zod` للتحقق من المدخلات، `hls.js` للمصدر HLS المرخّص وبـlazy import، `@playwright/test` dev لاختبارات الفشل/التبديل. PostCSS حُدّث تحديث patch للأمان. PGlite/Lighthouse/Chromium أدوات QA اختيارية خارج dependencies المشروع.

## 7. قائمة إطلاق واقعية

- [ ] مصدر/ترخيص فعلي، تطابق معرفات المباريات والقنوات، حقوق البلد/التضمين والاشتراك موثقة.
- [ ] بريد `LIVE_RIGHTS_EMAIL` حقيقي ومراقَب؛ النموذج **يفتح تطبيق البريد ولا يدّعي إرسالًا/استلامًا من الخادم**.
- [ ] `NEXT_PUBLIC_SITE_URL` صحيح، أسرار الخادم فقط، whitelist/CSP لا يحتوي نطاقات عامة غير مملوكة.
- [ ] Supabase migration/RLS/RPC تحقق عليها فعليًا إذا أردت البلاغات/الإدارة؛ اختبر طلبات متوازية وصلاحية anon من المشروع المنشور.
- [ ] اختبر مقدمي الفيديو الحقيقيين من المتصفح/النطاق المنشور: الملكية، autoplay/parent/CORS، geoblocking، وقفل الحقوق. الموكات لا تثبت هذا.
- [ ] بناؤك مع العلم مغلق ومفتوح ناجحان، واختبارات الوحدة والمتصفح والـRTL/mobile والأداء ناجحة.
- [ ] راجع Lighthouse في Preview والصفحة ذات البيانات الفعلية؛ قياسات lab للكتالوج الفارغ ليست وعدًا لأداء جميع الفيديوهات، ولا قياسات INP ميدانية.
- [ ] Vercel Hobby للاستخدام الشخصي غير التجاري فقط. الإعلانات/العمولات تتطلب Pro أو استضافة تسمح بالتجارة وترخيصًا مناسبًا؛ لا نحول أي فيديو عبر استضافة الموقع.
- [ ] افحص Preview ثم ادمج التغييرات بعد الموافقة. لم تُنشر مفاتيح أو روابط فعلية ولم تُطلق مهمة اكتشاف على حسابات حقيقية بهذه الجلسة.

### الإيقاف/الرجوع

أزل المصادر غير المصرح بها/اجعلها `failed` في الكتالوج الدائم أولًا؛ poll المتصفح/ISR لهما تأخير، فلا تعد بإيقاف كل تبويب قديم فورًا. بعدها عيّن `NEXT_PUBLIC_LIVE_ENABLED=false` وأعد النشر، وأوقف `LIVE_DISCOVERY_ENABLED` في GitHub لإيقاف استهلاك APIs. لا حاجة إلى تغيير طبقة النتائج. بدّل كلمة الإدارة/الأسرار إن لزم؛ تغيير كلمة الإدارة يبطل الجلسات الموقعة القديمة.

قائمة الملفات والتقسيم المرحلي: [CHANGES.md](./CHANGES.md). نتائج التحقق لهذه الجلسة: [QA.md](./QA.md).
