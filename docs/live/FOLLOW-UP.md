# مراجعة تكميلية لمركز البث الرسمي — 2026-10-01

كان مركز البث موجودًا بالفعل في نقطة البداية `cf3d105` (التنفيذ الأساسي في PR #8). هذه التغييرات **تدقيق وإصلاح للتنفيذ القائم**، وليست إعادة إضافة الميزة أو إعادة نشر مصادر الفيديو. سجل التنفيذ الأساسي يبقى في [CHANGES.md](./CHANGES.md) و[QA.md](./QA.md)؛ النتائج أدناه تخص المراجعة الحالية.

## ما أُصلح

1. **معرّفات آمنة للمسارات:** رفض `.` و`..`، وحجز `admin/copyright/disclaimer` لمعرّفات المباريات فقط. يبقى `matchId` معرّفًا خارجيًا؛ لا تعديلات على معرّفات طبقة النتائج.
2. **إتاحة موحّدة:** `coverageStreams` أساس عدّاد المصادر، زر «شاهد»، وروابط المصدر؛ `playableStreams` يختار البث القابل للتضمين من القائمة نفسها. فيديو مباشر انتهى أو انقضى `endsAt` لا يبقى مصدر بث نشطًا. موعد بدء مستقبلي لا يُشغّل مصدرًا موسومًا `live` مبكرًا، ومرور موعد مصدر `scheduled` لا يحوّله إلى مباشر.
3. **إعادة المشاهدة ليست مفترضة:** المباراة المنتهية تحتاج مصدر `highlights` معتمدًا، أو رابطًا رسميًا خارجيًا. `endsAt` لفيديو الملخص قد يكون وقت انتهاء التسجيل، ولا يُعامل تلقائيًا كوقت انتهاء ترخيص إعادة المشاهدة. الرابط الخارجي دليل منصة، وليس ضمانًا لنقل المباراة أو وجود إعادة.
4. **ساعة مشتركة:** مؤقت واحد كل 30 ثانية للإتاحة، وآخر كل ثانية للعد التنازلي، مشتركان بين البطاقات. مؤقتات الساعة تتوقف عند إخفاء التبويب وتُزال عند مغادرة آخر مشترك؛ الظهور يعيد التوقيت فورًا. هذا يعالج بقاء مصدر مخفي بعد انتهاء `hiddenUntil` عندما يعيد CDN البيانات نفسها، وإبقاء زر «شاهد» بعد انقضاء إتاحة المصدر.
5. **جلب متوقف فعلًا في الخلفية:** `isPaused` يغطي mount/manual/retry، لا polling وحده. إعادة المحاولة تتحقق من الظهور والاتصال عند جدولتها وعند تنفيذها؛ لا طلبات جديدة في التبويب المخفي/دون اتصال، ويُستأنف الجلب عند الظهور/عودة الاتصال. يبقى polling كل 45 ثانية وحدّ إعادة المحاولات قائمًا.
6. **اتساق الحالة:** إخفاء العد التنازلي التنظيمي القديم عند ورود حالة مباشرة من مصدر النتائج الحالي، دون افتراض وجود بث. رسالة فشل تحديث الكتالوج تقول «آخر نسخة متاحة» بدل الادعاء بأنها دائمًا النسخة المضمّنة.
7. **تأكيد بلاغ حقيقي:** HTTP 200 وحده ليس إيصالًا. تتحقق الواجهة بـZod من `{ accepted: true, duplicate: boolean }` قبل إظهار «تم استلام البلاغ».
8. **فحص YouTube دون إهمال ذيل القائمة:** تحفظ الدفعة مكانًا للاكتشافات الحية الجديدة، وتدوّر بقية المعرفات المرتبطة يدويًا حسب عدد زيارات القناة، بدل فحص أول 50 دائمًا. تبقى طلبات المهمة: بحث واحد لقناة مراجعة واحدة، ثم طلب metadata واحد كحد أقصى لـ50 فيديو؛ لا زيادة في عدد الطلبات أو ربط آلي بالمباريات. اختُبرت أعداد قنوات تقسم 96 لمنع تكرار الدفعة نفسها على كل زيارة.
9. **ترتيب زمني صحيح:** مقارنة UTC instants للمباريات والاكتشافات بدل الترتيب النصي لتواريخ ISO التي قد تحمل إزاحات زمنية مختلفة.

## الحدود والتشغيل

- لم تتغير `src/lib/**` أو صفحات النتائج/التفاصيل/النتائج المباشرة أو `src/app/api/matches/**`. لا API جديد ولا proxy فيديو، ولا تغيير لـwhitelist/CSP الافتراضية أو بيانات الإنتاج.
- `/live` و`/live/<matchId>` يحوّلان إلى `/{locale}/watch[/<matchId>]`. `/ar/live` و`/en/live` يظلان صفحات النتائج الأصلية. الصفحات العامة تبقى ISR كل 60 ثانية.
- الإعداد الافتراضي في `.env.example` يبقى **`NEXT_PUBLIC_LIVE_ENABLED=false`**. المعاينة فقط مبنية ومشغّلة بالقيمة `true`. لتفعيل النشر، اضبط العلم وأعد البناء/النشر.
- لم تُضف مباراة أو قناة أو رابط بث افتراضي للإنتاج، ولم تُشغّل مزامنة فعلية على API keys. قبل الإطلاق يلزم مراجعة حقوق ومصادر فعلية، بريد `LIVE_RIGHTS_EMAIL` مراقب، وSupabase الحقيقي إن أردت الإدارة/البلاغات. HLS يظل مغلقًا حتى مراجعة نطاقات الترخيص/CDN/CORS.
- لا نشر إلى Vercel أو دمج/دفع أو تغييرات بمشروع Supabase في هذه المراجعة. إعداد التشغيل والخطط التجارية وحدود الأتمتة في [README.md](./README.md).
- تحذير Edge Runtime deprecated وتحذير Node عن module type قائمان من البيئة السابقة؛ MockTimers في اختبارات Node الحالية يطبع تحذير experimental. لا أخطاء بناء أو lint أو أنواع بسببها.
