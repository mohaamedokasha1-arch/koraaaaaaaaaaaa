# تسليم المرحلة الأولى — تخصيص KoraScore بنهج local-first

**التاريخ:** 1 أكتوبر 2026.

**الفرع:** `arena/01a0f902-koraaaaaaaaaaaa`.

**الأساس المؤكد:** `f263a0d52fa14cac5c0d573678382d94377684cd`.

## 1. القرار والنطاق

أُنجز [فحص المرحلة صفر](./PERSONALIZATION-PHASE0-AUDIT.md) قبل تعديل التطبيق. أظهر الفحص أن الموقع يعمل بالفعل: نتائج ومواعيد وترتيب وهدافون، تفاصيل فرق ومباريات، بحث وكيانات عربية/إنجليزية، أخبار اختيارية، H2H وأرشيف، بث رسمي اختياري وPWA وSEO. لم يكن هناك حساب زائر أو مفضلة أو تخصيص للرئيسية.

اختار المستخدم **local-first** بعد مراجعة البنية والتكلفة: المفضلة وملف الزائر والرئيسية المخصصة الآن، دون إنشاء قاعدة بيانات أو خدمة مصادقة/بريد أو اشتراك. **نجاح هذا التسليم يخص هذا النطاق المعتمد؛ لا يعني اكتمال متطلبات الحسابات الأصلية.**

| المتطلب | الوضع الفعلي |
|---|---|
| التدقيق قبل التنفيذ وتوثيق الموجود/الناقص | ✅ موثق في تقرير المرحلة صفر، مع ملحق القرار المعتمد |
| مفضلة فرق وبطولات ولاعبين متاحين | ✅ إضافة/إلغاء وتخزين محلي، وهوية مستقلة عن اسم العرض |
| ملف شخصي أساسي | ✅ ملف **زائر** `/ar/profile` و`/en/profile`؛ ليس حسابًا سحابيًا |
| رئيسية مخصصة مع بقاء الرئيسية العامة | ✅ لوحة فوق الأقسام العامة، ويمكن تعطيلها دون فقد المفضلة |
| الخصوصية وإعادة الضبط | ✅ صفحة AR/EN، مسح بتأكيد، وتحذيرات صريحة لحدود التخزين |
| تسجيل/Google/بريد/استعادة وحذف حساب | ❌ مؤجل باختيار المستخدم؛ لا واجهة تسجيل صورية |
| مزامنة الأجهزة/الضيف مع حساب | ❌ مؤجلة؛ أحداث التخزين بين تبويبات المتصفح **ليست** مزامنة حسابات |
| حفظ مباريات وIn-app notifications | ❌ المرحلة الثانية، لم تبدأ |
| المقارنات والتحسينات الموسعة والتوقعات والنضج | ❌ المراحل 3–5، لم تبدأ |

## 2. ما بقي محفوظًا

- الاسم والشعار وSVG الأصلي، الهوية الداكنة navy/gold، الخطوط الأساسية وRTL/LTR. تغييرات قياس الرأس responsive فقط، وليست تغييرًا للشعار أو إعادة تصميم الموقع.
- جميع أقسام الرئيسية العامة، الصفحات والمسارات وواجهات API القائمة. لا تسجيل مطلوب لقراءة الأخبار أو النتائج.
- adapters والمزوّدون والكيانات والبحث وpipeline الأخبار والأرشيف والتاريخ وH2H كما هي؛ لم تُضف بيانات كرة قدم إنتاجية أو مزوّد بديل.
- مكونات عرض المباراة والخبر نفسها، مع تضييق أنواع القواميس وتمرير التوقيت إلى لوحة الأخبار دون تغيير سلوك الاستدعاءات القديمة.
- البث الرسمي الاختياري والقوائم الفارغة الفعلية وحقوق المصادر وPWA وعامل الخدمة الحالي.
- Canonical وhreflang وJSON-LD وsitemaps. لم تُضف الصفحات الشخصية إلى أي sitemap.
- لا تغيير لـ`package.json` أو `package-lock.json` أو ملفات المزوّدين والـSeed أو `vercel.json`. لا SDK حسابات، ولا analytics أو Push أو إعلانات جديدة.

## 3. المنفذ فعليًا

### المفضلة والتخزين

- وحدة مستقلة في `src/features/personalization`، مع `useSyncExternalStore` وSSR snapshot مجهول ثابت؛ لا قراءة لتفضيلات الزائر على الخادم.
- المفتاح `korascore:preferences:v1`؛ حد **60 اهتمامًا و64 KiB UTF-8**. الكتابة والقراءة تطبقان سقف الحجم، مع حجز مساحة لإيقاف التخصيص. لا تُحفظ كلمات مرور أو بريد أو رموز جلسة أو بيانات اتصال الزائر.
- المحفوظ: معرفات كرة قدم وبيانات عرض عامة محدودة، مثل اسم النادي/اللاعب وشعار موثوق وسياق صفحة المصدر، وإعداد إظهار اللوحة. حقول إضافية مثل `password/token/email/href` لا تُنسخ من المدخلات.
- التحقق من المعرفات، منع traversal، allowlist لشعارات المصادر الحالية، وإزالة التكرار بالهوية/مرجع المزود لا بمجرد الاسم.
- التخزين المحجوب أو الممتلئ يعمل **مؤقتًا في الذاكرة** مع تحذير، دون ادعاء الحفظ الدائم. الملف التالف لا يُكتب فوقه تلقائيًا؛ تُحتفظ بالعناصر الصالحة. النسخة المستقبلية تُقفل أمام التعديل المعتاد حتى إعادة ضبط صريحة.
- استقبال أحداث التخزين، وقراءة آخر كتابة قبل التعديل وبعد العودة لصفحة مشتركة عقب فترة بلا subscribers. تُحفظ تعديلات الذاكرة المؤقتة عند التنقل داخل التطبيق.
- لا معاملات atomic بين التبويبات: الكتابات المتزامنة قد تكون last-write-wins. لا ضمان استعادة بعد تنظيف المتصفح أو استمرار الوضع الخاص.

### نقاط المتابعة والملف

- أزرار في قوائم وتفاصيل الفرق والبطولات، وفي صفوف التشكيلة والهدافين **فقط مع معرف لاعب مدعوم**. لا أزرار تعتمد على الاسم وحده، ولا صفحة لاعب مستقلة مصطنعة.
- معرف اللاعب scoped للمزود `fd/af`، فلا يختلط اللاعب رقم 101 في مصدر مع الرقم نفسه في مصدر آخر. المشاركة في مباراة لا تُستنتج من متابعة اللاعب.
- الروابط تستخدم صفحات الفريق/البطولة/الهدافين/التشكيلة الموجودة، مع anchors للاعبين. مراجع ESPN تفيد التصفية، لكن رابط النادي يستخدم الـslug لأن adapter ESPN الحالي لا يدعم `getTeam`.
- كتالوج الملف من الكيانات القائمة والـcache فقط، بلا طلبات مزود إضافية لجلب لاعبين من أجل الملف. سقفه 120 فريقًا و100 لاعب و11 بطولة موجودة؛ هذا **ليس كتالوجًا لكل كرة القدم عالميًا**.
- مجموعات للمفضلة، بحث بالبدائل العربية/الإنجليزية، تبويبات ولوحة مفاتيح، عرض المزيد، إعداد التخصيص واللغة والتوقيت، ومسح محلي بتأكيد وإمكانية التراجع.
- أُعيد استعمال اختيار التوقيت الحالي وزيدت خياراته إلى **28 منطقة**؛ المصدر يبقى UTC والعرض بحسب اختيار الزائر.
- روابط الملف والخصوصية في التنقل، وإضافة رابط البحث إلى القائمة الصغيرة. أزرار المتابعة ليست داخل روابط. الرأس يصلح للشاشات الضيقة وللتابلت؛ القائمة الصغيرة محدودة بارتفاع الشاشة، قابلة للتمرير ودون رابط أخبار مكرر. ملف الزائر لا يُجلب مسبقًا لمجرد فتح القائمة.

### اللوحة الشخصية

- `HomeGate` لا يعرض لوحة ولا يرسل طلب تخصيص دون اهتمامات أو عند تعطيلها. renderer/fetcher الخاصان باللوحة محملان بصورة كسولة؛ الأقسام العامة لا تُحذف أو تُستبدل.
- المباشر والمواعيد والنتائج حسب اليوم المحلي؛ قراءة 1–3 buckets UTC لتغطية حدود اليوم وDST، مع تصفية نهائية بالتوقيت المختار.
- إعادة استعمال الخدمات العامة الحالية، بالتوازي ومع مشاركة القراءات العامة أثناء التنفيذ داخل instance دافئة. عدد العمليات لا يتضاعف بعدد المفضلة؛ **هذا ليس وعدًا بأن adapter يرسل طلب HTTP واحدًا**، فـESPN/TheSportsDB لهما fan-out داخلي قائم.
- تطابق فرق/بطولات بالمعرفات، مع dedup للتحديثات وأصل اللقطة؛ حدود العرض: مباشر6، مواعيد8، نتائج6، أخبار6. لا تحويل نتيجة مجهولة إلى صفر.
- أخبار من pipeline الحالي وبالكيانات المرتبطة فقط، مع ائتمان المصدر وروابطه. تبقى معطلة عندما لا يفعّل المشغّل feeds ملائمة؛ لا نسخ لمقالات أو تفعيل مصادر جديدة.
- حالات تحميل/تعذر/جزئي/فارغ/offline/stale وإعادة محاولة. التحديث الدوري كل60ث ويتوقف في التبويب المخفي أو offline، دون auto error retry. مهلة fetch20ث، وساعة عرض30ث تتوقف عند الإخفاء.
- علامة اللقطة القديمة لا تدّعي تحديثًا جديدًا. `fetchedAt` مأخوذ من نتيجة الخدمة العامة لا من وقت إنتاج الرد الشخصي؛ يبقى معنى وحداثة بيانات المزود خاضعين لطبقة التطبيع الحالية.
- SWR يحتفظ بلقطة مؤقتة داخل التبويب؛ **ليست مباراة محفوظة أو ضمانًا لعرض نتائج بعد إعادة تحميل offline**. عامل الخدمة يقدّم صفحة offline الصريحة، لا HTML خاصًا محفوظًا.

### API والخصوصية وSEO

- `POST /api/personalization/dashboard` للقراءة فقط. يرسل العميل team IDs/provider refs/league codes، لا أسماء العرض أو ملف تفضيلات كاملًا أو بيانات لاعب/حساب.
- JSON بحد فعلي **16 KiB**، بما في ذلك chunked bodies، ورفض UTF-8/JSON غير الصحيحين وMIME غير الصحيح. رفض cross-site/Origin غير مطابق قبل قراءة المصادر.
- مراعاة `Host` الحقيقي وبروتوكول الوسيط في التحقق: Next Node قد يحول URL الداخلي إلى localhost. لا اعتماد على `x-forwarded-host` مزور لتمرير Origin آخر.
- حد20طلبًا/دقيقة/instance-client دون crawler bypass على النقطة الجديدة. كل ردودها، بما فيها429، `private, no-store` و`noindex`. لا تخزين أو logging لملف الاهتمامات.
- الحماية ترث limiter المؤقت وforwarded IP الحاليين؛ **ليست حدًا موزعًا أو حماية مصادقة جاهزة**. الاستضافة قد تحتفظ بسجلاتها المعتادة، كما توضح صفحة الخصوصية.
- صفحة الملف `noindex, follow` مع `X-Robots-Tag` و`private, no-store`؛ الخصوصية أيضًا meta noindex. لا تقييد لفهرسة المحتوى العام.

**الأداء المرصود:** زيارة home بلا اهتمامات سجلت0طلبات تخصيص ولم تحمل chunk الذي يحتوي fetcher/validator اللوحة؛ زيارة متابع سجلت1طلبًا وchunk إضافيًا (~24 KiB JS غير مضغوط في القياس المحلي). هذا إثبات للعزل الكسول، **ليس مقارنة سرعة مع baseline أو نتيجة Lighthouse/CWV**. يوجد كود خفيف إضافي للتفضيلات، واستعمال الموقع والمزوّدين يظل له استهلاك؛ لا وعد تكلفة تشغيل صفرية.

**أخطاء عولجت أثناء الفحص:** ضيق رأس الملف وتمدد الرأس على320/تابلت، تقبل أصل المتصفح خلف الوسيط بدل403 كاذب، تغير تفضيلات أثناء غياب subscribers، سقف كتابة يمكن أن يتجاوز سقف القراءة، وروابط فرق ESPN غير المدعومة. أُعيدت الفحوص بعد الإصلاحات. تحذيرات Edge Runtime/MODULE_TYPELESS السابقة غير قاتلة ولم نغيّر بنية المشروع لإخفائها.

## 5. ما لا يمكن إثباته من هذا التسليم

- لا اعتماد حسابات/قاعدة بيانات/SMTP/OAuth/RLS أو مزامنة أو حذف حساب؛ مؤجلة صراحة. ملف الزائر لا يملك اسمًا أو صورة مستخدم أو كلمة مرور.
- لا تحقق لتغطية مفاتيح football-data/API-Football على إنتاج المستخدم، ولا ضمان أن المصادر تعرض كل مباراة/تشكيلة/لاعب. الـ200 في smoke الافتراضي يثبت تنفيذ الطلب والواجهة، لا صحة كل إحصائية خارجية أو SLA للمصدر.
- اللاعبون من squads/scorers المتاحة فقط؛ لا registry لاعب دائم أو إثبات مشاركة أو ربط أخبار لاعب موثوق. تتغير التشكيلات وروابط سياق اللاعب مع الوقت.
- registry الفرق ذاكرة لكل instance؛ تفاصيل الأندية المكتشفة خارج الـSeed قد لا تتوفر بعد cold start، خصوصًا المراجع التي لا يدعم مزودها تفاصيل فريق. الحفظ المحلي والهوية لا ينشئان مصدر بيانات غير موجود.
- لا اختبار فواتير/خطة Vercel الفعلية أو traffic/quota متعدد instances، ولا خدمة مراقبة/Push أو realtime worker جديد.
- لا نشر للإنتاج، ولا اختبار Search Console أو Google indexing أو ترتيب أو Core Web Vitals. لا تغييرات على خطة استضافة أو اشتراك.

## 6. المراجعة والتشغيل

1. من المعاينة افتح **مساحتي / My space**، أو `/ar/profile` و`/en/profile`.
2. اختر ناديًا/بطولة من الكتالوج الحقيقي، ثم افتح الرئيسية. اللوحة تظهر فوق المحتوى العام؛ عندما تنقص البيانات تظهر رسالة واضحة.
3. جرّب الإيقاف مع استمرار المفضلة، تبديل اللغة/التوقيت، ثم المسح بالتأكيد. سياسة التخزين في `/ar/privacy` و`/en/privacy`.
4. للنشر: احتفظ بإعدادات المزوّدين والأخبار والبث الحالية، واضبط `NEXT_PUBLIC_SITE_URL` للدومين الإنتاجي الصحيح. لا متغير حسابات جديد مطلوب لهذه المرحلة. اختبر توفر بياناتك الفعلية وحدود مزوّديك على Vercel؛ لا تستبدل الإعدادات بقيم الاختبار المحلية.
5. لإعادة اختبار المتصفح: ابنِ مع `NEXT_PUBLIC_LIVE_ENABLED=true` أولًا، وثبّت Chromium المناسب لـPlaywright في بيئتك، ثم `npm run test:e2e`. إعداد Playwright يشغّل fixtures منعزلة؛ ليست مطلوبة للمعاينة أو التشغيل الإنتاجي.

**نقطة التوقف:** انتهى نطاق المرحلة الأولى local-first بعد الفحوص أعلاه. لم تبدأ المرحلة الثانية، وتفعيل الحسابات أو حفظ المباريات/التنبيهات يحتاج قرار متابعة منفصلًا. التعديلات محفوظة على فرع الجلسة؛ لا commit/push أو نشر إنتاج أُجري ضمن هذا التسليم.
